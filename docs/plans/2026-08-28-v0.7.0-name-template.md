# v0.7.0 - Export Name Template

Date 2026-08-28. Builds `descript export` naming against the iDD language filename standard, LOCKED by Julian 2026-08-28 (canonical record - the "Course production" tab of the iDD naming standard Google Doc; local canonical copy at ~/Desktop/iDD-Naming-Convention/idd-language-filename-standard.md).

## The standard being implemented

Language files: `[Course Acronym] - [CC] - [LL] - [CODE Simplified Language Name] - [Lesson Name].ext`

- Segment = code + simplified English name, always, bracket-free. Nine simplified regional names (Spanish Latino, Spanish Spain, French Canada, French France, Portuguese Brazil, Portuguese Portugal, Chinese Simplified, Chinese Traditional, Serbian Latin).
- Latin American Spanish is written plain `ES` in filenames, never ES-419. Mapping records keep canonical es-419.
- English captions are a language file too (`EN English`).
- Vimeo cap 128 chars; over-cap = WARN loudly, never auto-trim (trimming the lesson name is an operator decision).
- Composition names in Descript are never touched; language mapping comes from creation-time records (translate report, LANGUAGE-INDEX).

## CLI surface

`descript export ... --names <file> [--name-template "<template>"]`

- `--names <file>` - naming manifest JSON. Reserved keys `template` (optional) and `languages` (composition id -> canonical language code, e.g. "fr-CA", "es-419", "en"). Every other top-level string key is a template field ({acronym}, {cc}, {ll}, {lesson}, {educator}, ...).
- `--name-template` - inline template override; wins over the manifest's `template`. Default template when naming is active: `{acronym} - {cc} - {ll} - {lang} - {lesson}`.
- Placeholders: `{lang}` (language segment via the built-in vocabulary), `{title}` (sanitized composition title), `{id}` (composition id), plus any manifest field. `{slug}` is NOT supported in export mode (not known pre-publish; pre-flight validation must run before any publish is submitted).
- Naming applies to export mode (positional pid[+cid], --composition-ids, --projects). `--resume` carries names through the prior report's `renderedName` fields; `download-published` is out of scope this release.

## Behavior

- When naming is active, files are written FLAT into outputDir (plus projectFolder for --projects) as `<renderedName>.<ext>` - no per-title folder, no claimFolder suffixing (uniqueness is enforced pre-flight).
- Pre-flight, before ANY publish is submitted (publishes are risk-bearing): every item must resolve a language (when {lang} is used), every referenced field must exist, unknown placeholders error, rendered names must be unique across the batch. Violations exit 2 listing every offender.
- Rendered names pass through the existing sanitize().
- Names longer than 128 chars WARN on stderr and set `nameOver128: true` in the report item; the file still writes.
- Report items gain `renderedName`; `--resume` prefers `renderedName` over sanitized title for exists-checks and threads it through re-runs.
